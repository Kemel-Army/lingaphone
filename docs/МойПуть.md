ТЗ: Модуль «Мой путь» (User Journey) и управление контентом учебников1. Глобальная логика и распределение пользователейВводное тестирование: Каждый новый ученик в обязательном порядке проходит живой пробный урок с преподавателем. Автоматического распределения по возрасту или классам в системе нет.  Роль куратора/учителя: По результатам пробного урока куратор или учитель вручную выставляет текущий уровень владения языком (CEFR) в панели администратора.  Генерация пути: На основе выбранного куратором уровня система автоматически активирует для ученика соответствующий учебный трек («Мой путь») и привязывает к его аккаунту определенный учебник.  2. Структура базы данных и контента (Пед-модель)Основной цифровой путь ученика строится вокруг интерактивного учебника. Живые уроки фиксируются в системе только количественно.  Каждая книга должна иметь строгую иерархию:$$\text{Уровень (CEFR)} \rightarrow \text{Учебник} \rightarrow \text{Разделы/Блоки} \rightarrow \text{Тесты}$$Согласно утвержденной матрице, в систему заводится следующая сетка сопоставления:  ВозрастКлассУровень (CEFR)Учебник (Main course books)5–71Pre-beginnerPhonics 1 + Fairyland 17–81–2Pre-beginnerPhonics 2 + Fairyland 28–92–3Pre-beginnerFairyland 3 (+ Phonics 3)9–103–4Beginner A1Fairyland 410–114–5Beginner A1Access 111–135–7Beginner A1Spark 112–136–7Elementary A2Access 213–187–11Elementary A2Spark 2⚠️ Исключения: Учебники Spark 3, Spark 4 и On Screen B2+ полностью исключаются из разработки и в базу данных не заносятся.  На каждый уровень (курс) закладывается продолжительность в 1 учебный год.  3. Функциональные требования3.1. Интерфейс Куратора (Админ-панель)Реализовать карточку ученика с возможностью выбора уровня из выпадающего списка (согласно таблице выше).  При сохранении уровня система должна автоматически привязать к ученику нужную книгу и открыть к ней доступ.  3.2. Интерфейс Ученика («Мой путь»)Отображение текущего учебника в виде последовательной карты уроков.  Разделение книги на блоки (модули/главы).  Геймификация и ограничения: Доступ к следующему блоку закрыт, пока не пройден текущий.  3.3. Модуль тестирования и замеров эффективностиВ конце каждого блока/раздела учебника должен быть внедрен обязательный проверочный тест.  Полноценное прохождение блока засчитывается только после успешной сдачи теста.  Система должна сохранять результаты тестов для формирования аналитики (замеров эффективности обучения).  4. Критерии приемки текущего этапа (Этап тестирования)В систему заведены новые книги от методиста (за исключением Spark 3, 4 и On Screen).  Для пилотного учебника (например, Access 1) полностью создана структура и наполнение для первых 3 блоков.  Проверена ручная смена уровня куратором: при переключении уровня в админке у ученика корректно меняется доступный учебник.
